# Glossary

| Term | Simple Meaning |
|---|---|
| auditability | Ability to investigate where data came from |
| base table | Table used as a source |
| business interface | Data interface designed around a business need |
| business-ready data | Data with documented grain, rules, and validation |
| change sensitivity | How easily consumers may be affected by changes |
| clean layer | Standardised data layer with documented rules |
| clean table | Stored clean data with stable grain |
| consumer | Person, process, report, or query using data |
| CTE | Named query step inside one SQL statement |
| current-state interface | Interface showing latest accepted state |
| data interface | Way data is exposed for use |
| dependency | Source object or rule an interface relies on |
| exception output | Rows needing review |
| freshness | How current the data needs to be |
| history interface | Interface that preserves past rows |
| interface grain | What one interface row represents |
| one-time logic | Logic needed for one temporary question |
| output grain | What one output row represents |
| persistence | Whether rows or objects remain beyond one query |
| query definition | SQL logic that produces output |
| raw layer | Source-aligned layer preserving history |
| raw table | Stored raw source data |
| reporting layer | Consumer-focused layer |
| reporting table | Stored reporting result |
| reporting view | Reusable reporting query definition |
| reusable interface | Interface used by more than one query or consumer |
| source grain | What one source row represents |
| stored result | Data saved as rows |
| subquery | Query embedded inside another query |
| table | Object that stores rows |
| validation | Checks proving output can be trusted |
| view | Named reusable query definition |
