# Glossary

| Term | Simple meaning |
|---|---|
| `.git` | Folder that stores Git metadata and history |
| `.gitignore` | File containing ignore rules |
| Branch concept | Separate line of work, introduced later |
| Commit | Recorded logical change |
| Commit hash | Identifier for a commit |
| Commit history | Sequence of commits |
| Diff | View of line-level changes |
| Distributed version control | Version control where local repositories can contain history |
| Git | Version control tool |
| GitHub | Hosted collaboration platform built around Git |
| HEAD | Current checked-out commit conceptually |
| History | Recorded commit sequence |
| Ignored file | File Git normally leaves out because of ignore rules |
| Index | Another name for the staging area |
| Local commit | Commit recorded on the local machine |
| Local repository | Git repository on your machine |
| Modified file | Tracked file changed since last commit |
| Remote repository concept | Hosted/shared repository, covered later |
| Repository | Project managed by Git |
| Repository root | Top-level folder of a repository |
| Reproducibility | Ability to trace which version produced a result |
| Snapshot | Beginner mental model for a recorded project state |
| Staged file | File selected for the next commit |
| Staging area | Place where selected changes wait |
| Status | Current Git state summary |
| Tracked file | File Git already knows about |
| Untracked file | New file Git does not yet track |
| Version control | System for recording change history |
| Working directory | Current project folder being worked in |
| Working tree | Current checked-out project files |
